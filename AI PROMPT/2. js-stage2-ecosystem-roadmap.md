## PHASE 1 — React Sâu

*Không phải React cơ bản. Đây là cách React thật sự hoạt động bên trong.*

### 1.1 — Fiber Architecture & Reconciliation

- 🔴 Stack reconciler cũ vs Fiber — tại sao React rewrite hoàn toàn
- 🔴 Fiber node là gì — linked list, không phải tree đơn giản
- 🔴 Render phase vs Commit phase — render có thể bị interrupt, commit không
- 🔴 Work loop — cách React chia nhỏ work thành units, yield lại cho browser
- 🔴 Double buffering — current tree vs work-in-progress tree
- 🔴 Reconciliation algorithm — diffing rules: same type, same key
- 🔴 Keys — tại sao cần, tại sao index làm key gây bug
- 🟡 Priority lanes — không phải mọi update đều được xử lý bình đẳng
- 🟡 Batching — React 18 automatic batching, tại sao ít re-render hơn
- 🟢 Fiber node structure — stateNode, pendingProps, memoizedProps, effectTag
- 🟢 React Devtools Profiler — đọc flame chart, tìm unnecessary re-renders

### 1.2 — Concurrent Mode

- 🔴 Concurrent Mode là gì — interruptible rendering, không block main thread
- 🔴 `startTransition` — đánh dấu update là non-urgent, có thể bị preempt
- 🔴 `useTransition` — track pending state của transition
- 🔴 `useDeferredValue` — defer giá trị, tránh block urgent update
- 🔴 `Suspense` — bắt Promise, hiển thị fallback trong khi chờ
- 🟡 Suspense boundaries — nest nhiều boundaries, granular loading states
- 🟡 `use()` hook (React 19) — read Promise và Context trong render
- 🟡 Streaming SSR với Suspense — server stream HTML từng phần
- 🟢 Time slicing — cách React schedule work theo 5ms chunks
- 🟢 Scheduler package — internals của React's task scheduler

### 1.3 — React Server Components (RSC)

- 🔴 RSC là gì — component chạy trên server, zero JS bundle gửi xuống client
- 🔴 RSC vs SSR — khác nhau căn bản. SSR render HTML. RSC là component model mới
- 🔴 RSC vs Client Components — khi nào dùng cái nào
- 🔴 "use client" directive — boundary giữa server và client tree
- 🔴 "use server" directive — Server Actions, form submission không cần API route
- 🔴 Data fetching trong RSC — async component, không cần useEffect, không cần state
- 🔴 RSC serialization — chỉ serializable data được truyền từ server sang client
- 🟡 RSC payload format — binary protocol, không phải JSON thông thường
- 🟡 Composition patterns — server component wrap client component
- 🟡 Third-party libraries với RSC — nhiều thư viện chưa compatible
- 🟢 RSC protocol internals — flight format
- 🟢 Edge RSC — chạy RSC ở edge runtime

### 1.4 — Hooks Internals

- 🔴 Hooks linked list — React lưu hook state theo order, lý do Rules of Hooks
- 🔴 `useState` internals — queue, batching, tại sao state không update ngay lập tức
- 🔴 `useReducer` — tại sao React recommend cho complex state
- 🔴 `useEffect` — dependency array comparison (Object.is), cleanup function
- 🔴 `useLayoutEffect` — chạy synchronously sau DOM mutation, trước paint
- 🔴 `useRef` — mutable container, không trigger re-render, persist qua renders
- 🔴 `useMemo` — cache computed value, dependency array
- 🔴 `useCallback` — cache function reference, tránh unnecessary re-render của children
- 🔴 `useContext` — mọi consumer re-render khi value đổi, performance implication
- 🔴 Custom hooks — extract stateful logic, composition pattern
- 🟡 `useImperativeHandle` + `forwardRef` — expose imperative API từ component
- 🟡 `useId` — stable unique ID cho SSR hydration
- 🟡 `useSyncExternalStore` — integrate external store với React
- 🟡 `useInsertionEffect` — CSS-in-JS, chạy trước layout effects
- 🟢 Hook identity — tại sao hook không thể đổi số lần gọi giữa các renders
- 🟢 React 19 hooks mới — `use`, `useOptimistic`, `useFormStatus`

### 1.5 — Performance trong React

- 🔴 Re-render — khi nào xảy ra: state đổi, props đổi, parent re-render, context đổi
- 🔴 `React.memo` — shallow comparison props, khi nào hiệu quả, khi nào không
- 🔴 Context re-render problem — tách context thành nhiều piece nhỏ
- 🔴 Component composition — lift children up để tránh unnecessary re-render
- 🔴 List virtualization — chỉ render visible items (TanStack Virtual)
- 🟡 `useCallback` / `useMemo` trade-offs — có cost, không phải free optimization
- 🟡 Profiler API — `<Profiler onRender>` để measure render time
- 🟡 React DevTools — Highlight Updates, Profiler flame chart
- 🟡 Lazy loading components — `React.lazy` + `Suspense`
- 🟡 Code splitting tại route level — giảm initial bundle
- 🟢 Concurrent features và performance — Offscreen API (future)
- 🟢 React Compiler (React Forget) — automatic memoization

### 1.6 — Patterns Thực tế

- 🔴 Compound components — `<Select>` + `<Select.Option>` share state ngầm
- 🔴 Render props — truyền function làm children hoặc prop
- 🔴 Higher-Order Components (HOC) — wrapper pattern, khi nào còn hợp lý
- 🔴 Controlled vs Uncontrolled components — form inputs, trade-offs
- 🔴 Error boundaries — class component, bắt render errors
- 🔴 Portal — render ra ngoài DOM hierarchy (modal, tooltip, dropdown)
- 🟡 Headless UI components — logic tách khỏi styling
- 🟡 Polymorphic components — `as` prop, render element khác nhau
- 🟡 Slots pattern — composition thay vì props drilling

## PHASE 2 — Next.js Production

### 2.1 — App Router (hiểu thật sâu)

- 🔴 File conventions — `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx`
- 🔴 Layouts — shared UI, không re-mount khi navigate, nested layouts
- 🔴 `error.tsx` — Error boundary tự động, `reset()` function
- 🔴 `loading.tsx` — Suspense boundary tự động, streaming
- 🔴 Route Groups `(group)` — tổ chức routes, không ảnh hưởng URL path
- 🔴 Dynamic routes `[slug]`, `[...slug]`, `[[...slug]]`
- 🔴 Route Handlers — `route.ts`, thay thế API routes của Pages Router
- 🔴 Middleware — chạy trước request, auth check, redirect, rewrite
- 🟡 Parallel Routes `@slot` — render nhiều pages trong cùng layout
- 🟡 Intercepting Routes `(.)` — modal pattern, URL vẫn đúng
- 🟡 `generateStaticParams` — static generation cho dynamic routes
- 🟡 `generateMetadata` — dynamic SEO metadata
- 🟢 Route segment config — `dynamic`, `revalidate`, `runtime` per-route
- 🟢 Draft mode — preview unpublished content

### 2.2 — Rendering Strategies

- 🔴 Static Rendering — render lúc build, cache vĩnh viễn, nhanh nhất
- 🔴 Dynamic Rendering — render mỗi request, luôn fresh
- 🔴 Streaming — render và send HTML từng phần, không block toàn bộ page
- 🔴 `fetch` với caching options — `cache: 'force-cache'`, `cache: 'no-store'`, `next: { revalidate }`
- 🔴 `revalidatePath` / `revalidateTag` — on-demand ISR
- 🔴 Khi nào trang tự động dynamic — cookies(), headers(), searchParams
- 🟡 PPR (Partial Prerendering) — static shell + dynamic holes
- 🟡 ISR với Time-based revalidation — `next: { revalidate: 60 }`
- 🟡 ISR với On-demand revalidation — webhook trigger revalidate
- 🟢 Edge Runtime rendering — limitations, khi nào dùng
- 🟢 React cache() function — deduplicate requests trong RSC tree

### 2.3 — Data Fetching Patterns

- 🔴 Fetch trong Server Component — async component, no useEffect
- 🔴 Server Actions — form submission, mutation không cần API route
- 🔴 `useFormState` / `useActionState` — track action state ở client
- 🔴 `useFormStatus` — pending state của form submission
- 🔴 Optimistic updates với `useOptimistic`
- 🟡 Parallel data fetching — `Promise.all` trong server component
- 🟡 Sequential vs parallel fetching — trade-offs
- 🟡 `cache()` — memoize expensive function trong request lifecycle
- 🟢 Streaming với `<Suspense>` — progressive rendering từng phần

### 2.4 — 4 Caching Layers

- 🔴 Request Memoization — deduplicate fetch trong cùng render tree, reset mỗi request
- 🔴 Data Cache — persist fetch results qua requests và deployments
- 🔴 Full Route Cache — cache HTML + RSC payload lúc build
- 🔴 Router Cache — client-side cache, tránh network trip khi navigate lại
- 🔴 Cách invalidate mỗi layer — revalidatePath, revalidateTag, cache: 'no-store'
- 🟡 Cache busting strategies — khi nào mỗi layer expire
- 🟡 Opt-out của specific layers — khi nào cần
- 🟢 Cache internals — file system cache, in-memory cache

### 2.5 — Deployment & Optimization

- 🔴 Vercel deployment — zero-config, automatic preview deployments
- 🔴 `next/image` — lazy loading, format optimization (WebP/AVIF), sizing
- 🔴 `next/font` — self-hosted fonts, layout shift elimination
- 🔴 `next/link` — prefetching, client-side navigation
- 🔴 Bundle analysis — `@next/bundle-analyzer`, tìm large packages
- 🟡 Edge vs Node.js runtime — trade-offs, `runtime: 'edge'`
- 🟡 Environment variables — `.env.local`, `NEXT_PUBLIC_` prefix
- 🟡 Security headers — Content-Security-Policy, HSTS trong `next.config.js`
- 🟡 Internationalization — `next-intl`, locale routing
- 🟢 Self-hosting Next.js — standalone output, Docker
- 🟢 OpenTelemetry integration — tracing trong Next.js

## PHASE 4 — TypeScript Nâng cao

*Không phải TypeScript cơ bản. Đây là thứ phân biệt người dùng TypeScript với người hiểu TypeScript.*

### 4.1 — Type System Fundamentals (sâu)

- 🔴 Structural typing — duck typing, không phải nominal typing
- 🔴 Type widening và narrowing — cách TypeScript mở rộng và thu hẹp types
- 🔴 Excess property checking — chỉ xảy ra khi assign trực tiếp
- 🔴 `unknown` vs `any` — `unknown` force bạn narrow trước khi dùng
- 🔴 `never` — bottom type, unreachable code, exhaustive checking
- 🔴 Type guards — `typeof`, `instanceof`, `in`, custom type guard function
- 🔴 Discriminated unions — `type` field để narrow union
- 🟡 Covariance và Contravariance — function parameters contravariant, return covariant
- 🟡 Bivariance (function members trong interface) — historical quirk
- 🟢 TypeScript strict flags — `strictFunctionTypes`, `strictNullChecks`, `noUncheckedIndexedAccess`

### 4.2 — Generics Nâng cao

- 🔴 Generic constraints — `<T extends object>`, `<T extends keyof U>`
- 🔴 Default generic parameters — `<T = string>`
- 🔴 `infer` keyword — extract type từ bên trong type khác
- 🔴 Conditional types — `T extends U ? X : Y`
- 🔴 Distributive conditional types — `T extends U` với union types
- 🔴 Mapped types — `{ [K in keyof T]: ... }`
- 🔴 `keyof`, `typeof`, `ReturnType<>`, `Parameters<>`, `Awaited<>`
- 🟡 Template literal types — `type EventName = \`on${string}\``
- 🟡 Recursive types — `type DeepPartial<T>`
- 🟡 `as` trong mapped types — key remapping
- 🟡 Variance annotations — `in`, `out` modifiers (TS 4.7+)
- 🟢 Higher-kinded types simulation — workaround trong TS
- 🟢 Type-level programming — type challenges level

### 4.3 — Utility Types (tất cả, không bỏ sót)

- 🔴 `Partial<T>`, `Required<T>`, `Readonly<T>`
- 🔴 `Pick<T, K>`, `Omit<T, K>`
- 🔴 `Record<K, V>`
- 🔴 `Exclude<T, U>`, `Extract<T, U>`
- 🔴 `NonNullable<T>`
- 🔴 `ReturnType<F>`, `Parameters<F>`, `ConstructorParameters<C>`
- 🔴 `Awaited<T>` — unwrap Promise type
- 🔴 `InstanceType<C>`
- 🟡 `ThisParameterType<F>`, `OmitThisParameter<F>`
- 🟡 Tự build utility types — hiểu cơ chế thay vì chỉ dùng
- 🟡 `NoInfer<T>` (TS 5.4) — prevent type widening trong generics

### 4.4 — Patterns Thực tế

- 🔴 `satisfies` operator — validate type mà không widening
- 🔴 `as const` — literal types, readonly tuples
- 🔴 Declaration merging — extend module types, augment global
- 🔴 Module augmentation — thêm types cho third-party modules
- 🔴 Type narrowing với assertion functions — `asserts value is T`
- 🟡 Branded types — nominal typing workaround: `type UserId = string & { __brand: 'UserId' }`
- 🟡 `Opaque<T>` pattern — type-safe IDs, prevent mixing up strings
- 🟡 Builder pattern với TypeScript — step-by-step type inference
- 🟢 TypeScript compiler API — AST, type checker, code generation
- 🟢 Custom transformers — compile-time code generation

### 4.5 — Zod Deep Dive

- 🔴 Primitive schemas — string, number, boolean, date
- 🔴 Object schemas — strict, passthrough, strip
- 🔴 Array, tuple, union, intersection schemas
- 🔴 `z.infer<>` — derive TypeScript type từ schema
- 🔴 `.transform()` — parse và transform data
- 🔴 `.refine()` — custom validation logic
- 🔴 Error formatting — `ZodError`, custom error messages
- 🟡 Discriminated union schemas
- 🟡 `.superRefine()` — fine-grained error control
- 🟡 Schema composition — extend, merge, pick, omit schemas
- 🟡 Coerce — `z.coerce.number()` cho form inputs (string → number)

## PHASE 5 — Backend Node.js Production

### 5.1 — Framework: Hono hoặc Fastify

**Hono (recommended cho modern projects)**
- 🔴 Router, middleware, context — cú pháp, request/response handling
- 🔴 Type-safe routing — `app.get('/users/:id', handler)`
- 🔴 Built-in middleware — cors, logger, compress, cache
- 🔴 Hono với Next.js Route Handlers — dùng làm API layer
- 🔴 Deploy targets — Vercel, Cloudflare Workers, Node.js, Deno, Bun
- 🟡 RPC mode — type-safe client từ server definitions (tương tự tRPC)
- 🟡 Streaming responses — `streamText`, `streamSSE`
- 🟢 Hono middleware pattern — tạo custom middleware

**Fastify (recommended cho complex backend)**
- 🔴 Plugin system — encapsulation, scope, dependency injection
- 🔴 Schema validation — JSON Schema cho request/response, auto-docs
- 🔴 `fastify-plugin` — chia sẻ plugin giữa scopes
- 🟡 Decorators — extend request/reply/fastify instance
- 🟡 Hooks — onRequest, preHandler, onSend, onError
- 🟡 Graceful shutdown — drain connections, cleanup plugins
- 🟢 Benchmarking — tại sao Fastify nhanh hơn Express

### 5.2 — Authentication Production-Grade

- 🔴 JWT structure — header.payload.signature, không encrypt, chỉ sign
- 🔴 Access token (short-lived, 15 phút) + Refresh token (long-lived, 7 ngày)
- 🔴 Refresh token rotation — mỗi lần dùng issue mới, invalidate cũ
- 🔴 Refresh token family detection — phát hiện token theft
- 🔴 HttpOnly cookie cho refresh token — không accessible từ JS
- 🔴 Password hashing — Argon2id (preferred) hoặc bcrypt, tại sao không MD5/SHA
- 🔴 Session management với Redis — store session, invalidate on logout
- 🟡 OAuth2 Authorization Code + PKCE — cho web app, không dùng Implicit flow
- 🟡 PKCE — Proof Key for Code Exchange, tại sao cần
- 🟡 Social login — Google, GitHub OAuth integration
- 🟡 MFA — TOTP (Google Authenticator), backup codes
- 🟡 Email verification, password reset flows
- 🟡 Auth libraries: Lucia, Better Auth, Auth.js — trade-offs
- 🟢 WebAuthn / Passkeys — tương lai của authentication
- 🟢 RBAC — Role-Based Access Control, permission system

### 5.3 — API Design

- 🔴 REST resource design — noun not verb, `/users/{id}/posts` not `/getUserPosts`
- 🔴 HTTP methods đúng — GET (idempotent), POST, PUT (idempotent), PATCH, DELETE
- 🔴 Status codes đúng — 200, 201, 204, 400, 401, 403, 404, 409, 422, 429, 500
- 🔴 Error response format — consistent structure, machine-readable
- 🔴 Request validation — validate input trước khi xử lý, Zod hoặc JSON Schema
- 🔴 Pagination — cursor-based (recommended) vs offset-based
- 🔴 Filtering, sorting — query parameters design
- 🟡 API versioning — URL versioning `/v1/` vs header versioning
- 🟡 Idempotency keys — safe retry cho mutation, lưu trong Redis
- 🟡 Rate limiting — per-user, per-IP, sliding window pattern
- 🟡 Circuit breaker — fail fast khi downstream service down
- 🟡 Request ID — trace request qua logs
- 🟡 tRPC — type-safe API, shared types giữa server và client
- 🟢 OpenAPI spec — generate từ code hoặc code từ spec
- 🟢 GraphQL — khi nào thật sự cần, N+1 problem, DataLoader

### 5.4 — File Upload & External Services

- 🔴 Multipart form data parsing — `@fastify/multipart`, stream xử lý
- 🔴 Presigned URLs — client upload thẳng lên S3/R2, bypass server
- 🔴 Cloudflare R2 hoặc AWS S3 — object storage

- 🔴 Dead letter queue — failed jobs sau max retries
- 🔴 Job events — completed, failed, progress

## PHASE 6 — Database Layer

### 6.1 — PostgreSQL Thật Sự (không chỉ biết query)

- 🔴 Data types — chọn đúng type: `uuid` vs `bigserial`, `text` vs `varchar`, `jsonb` vs `json`
- 🔴 Constraints — `NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY`, `ON DELETE CASCADE/RESTRICT`
- 🔴 Indexes — B-tree (default), khi nào cần, khi nào index làm chậm hơn (write overhead)
- 🔴 `EXPLAIN ANALYZE` — đọc query plan, nhận ra Seq Scan vs Index Scan vs Bitmap Scan
- 🔴 JOIN types — INNER, LEFT, RIGHT, FULL — khi nào dùng cái nào
- 🔴 Transactions — `BEGIN`, `COMMIT`, `ROLLBACK`, isolation levels
- 🔴 Isolation levels — Read Committed (default), Repeatable Read, Serializable
- 🔴 Race conditions — dirty read, non-repeatable read, phantom read
- 🟡 Composite indexes — column order matters
- 🟡 Partial indexes — `CREATE INDEX ON orders (user_id) WHERE status = 'active'`
- 🟡 GIN indexes — cho JSONB, array, full-text search
- 🟡 `pg_stat_statements` — tìm slow queries trong production
- 🟡 Vacuuming — MVCC, dead tuples, autovacuum
- 🟡 Connection limits — tại sao Postgres có giới hạn connections
- 🟢 Table partitioning — range, list, hash partitioning cho large tables
- 🟢 Materialized views — precomputed query results
- 🟢 Row Level Security (RLS) — policy-based access control

### 6.2 — Prisma (ORM Layer)

- 🔴 Schema definition — models, relations, field types
- 🔴 Migrations — `prisma migrate dev`, `prisma migrate deploy`
- 🔴 CRUD operations — `findMany`, `findUnique`, `create`, `update`, `delete`
- 🔴 Relations — `include`, `select`, nested writes
- 🔴 Filtering — `where` với operators: `equals`, `in`, `contains`, `gte`, `lt`
- 🔴 N+1 problem — nhận ra và fix với `include`
- 🔴 Transactions — `prisma.$transaction([])`
- 🟡 Raw queries — `prisma.$queryRaw`, `prisma.$executeRaw`
- 🟡 Pagination — cursor-based với `cursor` + `take`, skip-based với `skip` + `take`
- 🟡 Soft delete pattern — `deletedAt` field, global middleware
- 🟡 Multi-tenancy — tenant isolation trong schema
- 🟢 Prisma Accelerate — connection pooling + edge caching
- 🟢 Custom generators — generate từ Prisma schema

### 6.3 — Drizzle (Alternative ORM)

- 🟡 Schema definition — TypeScript-first, SQL-like syntax
- 🟡 Query builder — type-safe, gần với raw SQL hơn Prisma
- 🟡 Migrations — drizzle-kit generate và migrate
- 🟡 Relations — one-to-one, one-to-many, many-to-many
- 🟢 Drizzle vs Prisma — khi nào chọn cái nào

### 6.4 — Redis

- 🔴 Data structures — String, Hash, List, Set, Sorted Set — khi nào dùng cái nào
- 🔴 Caching pattern — cache-aside, TTL, invalidation
- 🔴 Session storage — lưu session data thay vì stateless JWT
- 🔴 Rate limiting — sliding window với Sorted Set
- 🟡 Pub/Sub — real-time messaging, event broadcasting
- 🟡 Streams — append-only log, consumer groups
- 🟡 Lua scripting — atomic operations phức tạp
- 🟡 Redis Cluster — horizontal scaling
- 🟢 RedisSearch — full-text search với Redis

### 6.5 — Database Design Patterns

- 🔴 Normalization — 1NF, 2NF, 3NF — khi nào normalize, khi nào denormalize
- 🔴 Soft delete vs Hard delete — trade-offs, foreign key implications
- 🔴 Audit logging — track changes, `created_at`, `updated_at`, `created_by`
- 🔴 Pagination design — cursor-based cho large tables
- 🟡 Multi-tenancy patterns — row-level, schema-level, database-level
- 🟡 Event sourcing — store events thay vì current state
- 🟡 Optimistic locking — `version` field, prevent lost updates
- 🟢 CQRS — Command Query Responsibility Segregation
- 🟢 Database migration với zero downtime — expand/contract pattern

## PHASE 7 — Testing Production-Grade

### 7.1 — Testing Strategy

- 🔴 Testing pyramid — Unit → Integration → E2E, tỷ lệ và khi nào dùng từng loại
- 🔴 Test theo behaviour, không theo implementation — test cái user thấy, không test internals
- 🔴 Arrange, Act, Assert — cấu trúc một test tốt
- 🔴 Test isolation — mỗi test độc lập, không phụ thuộc thứ tự

### 7.2 — Unit & Integration Testing (Vitest)

- 🔴 `describe`, `it`/`test`, `expect` — cấu trúc cơ bản
- 🔴 Matchers — `toBe`, `toEqual`, `toContain`, `toThrow`, `toHaveBeenCalled`
- 🔴 Mocking — `vi.mock`, `vi.fn`, `vi.spyOn`
- 🔴 Setup/teardown — `beforeEach`, `afterEach`, `beforeAll`, `afterAll`
- 🔴 Test doubles — mock vs stub vs spy vs fake — phân biệt
- 🟡 Mock modules — mock imports, mock env variables
- 🟡 Snapshot testing — khi nào hữu ích, khi nào gây noise
- 🟡 Code coverage — line, branch, function coverage — không phải goal, là tool

### 7.3 — React Testing Library

- 🔴 Principles — test như user, không test implementation details
- 🔴 Queries — `getByRole`, `getByText`, `getByLabelText` (preferred), `getByTestId` (last resort)
- 🔴 `userEvent` — simulate user interactions đúng cách
- 🔴 Async testing — `waitFor`, `findBy` queries
- 🔴 `render`, `screen` — render component và query DOM
- 🟡 Custom renders — wrap với providers (theme, query client, router)
- 🟡 Mock fetch / TanStack Query — test data fetching components
- 🟡 Accessibility queries — `getByRole` theo ARIA roles

### 7.4 — API Testing

- 🔴 Test route handlers — mock database, test request/response
- 🔴 Supertest hoặc Hono test client — HTTP assertion
- 🔴 Test authentication — mock auth, test protected routes
- 🟡 Database testing — test với real database (test container)
- 🟡 Contract testing — Pact — verify API contracts giữa services

### 7.5 — E2E Testing (Playwright)

- 🔴 Page object model — tách locators và actions ra khỏi test
- 🔴 Locators — `getByRole`, `getByText`, `getByLabel` — prefer accessible locators
- 🔴 Actions — `click`, `fill`, `select`, `drag`
- 🔴 Assertions — `expect(locator).toBeVisible()`, `toHaveText()`, `toHaveURL()`
- 🔴 Fixtures — setup/teardown, shared state giữa tests
- 🟡 Authentication fixture — login một lần, reuse session
- 🟡 API mocking trong E2E — `page.route()` intercept requests
- 🟡 Visual testing — screenshot comparison
- 🟡 CI integration — headless mode, test sharding
- 🟢 Trace viewer — debug failed tests
- 🟢 Mobile emulation — test responsive design

### 7.6 — Accessibility Testing

- 🔴 `jest-axe` — automated a11y checks trong unit tests
- 🔴 Playwright a11y — `@axe-core/playwright`
- 🟡 Manual screen reader testing — không thể automate hoàn toàn
- 🟡 Keyboard navigation testing
