### 2.1 — React Sâu (không phải React cơ bản)

**Reconciliation & Fiber Architecture**

- Fiber là gì — tại sao React rewrite từ stack reconciler sang fiber
- Render phase vs Commit phase — khác nhau và tại sao quan trọng
- Work loop — cách React chia nhỏ work thành units, yield lại cho browser
- Priority lanes — không phải mọi update đều bình đẳng

**Concurrent Mode**

- `startTransition` — đánh dấu update là non-urgent
- `useDeferredValue` — defer giá trị thay vì action
- `Suspense` — không phải chỉ cho lazy loading, là primitive cho async UI
- Streaming SSR với Suspense — server stream HTML theo từng phần

**React Server Components (RSC)**

- Cơ chế thật: RSC chạy trên server, không có JS bundle gửi xuống client
- RSC vs SSR — khác nhau căn bản, không phải cùng một thứ
- "use client" / "use server" directives — boundary giữa server và client
- Data fetching patterns với RSC — không cần useEffect, không cần state

**Hooks Internals**

- Tại sao Rules of Hooks tồn tại — linked list bên trong, không phải arbitrary rule
- `useState` bên trong là gì — queue, batching, tại sao state không update ngay
- `useEffect` dependency array — cơ chế so sánh, shallow equality
- `useRef` — tại sao không trigger re-render, mutable container
- `useMemo` / `useCallback` — khi nào thật sự cần, khi nào premature optimization
- Custom hooks — composition pattern, không phải magic

**Performance trong React**

- Re-render — tại sao xảy ra, tại sao không phải lúc nào cũng xấu
- `React.memo` — shallow comparison, khi nào hiệu quả, khi nào không
- Context re-render problem — tất cả consumer re-render khi value đổi
- Profiler — đọc flame chart của React DevTools

### 2.2 — Next.js Production

**App Router (hiểu thật sâu)**

- File-based routing — layout, page, loading, error, not-found
- Nested layouts — shared UI, layout không re-mount khi navigate
- Route Groups `(group)` — organize routes không ảnh hưởng URL
- Parallel Routes `@slot` — render nhiều page trong cùng layout
- Intercepting Routes — modal pattern mà URL vẫn đúng

**Rendering Strategies — khi nào dùng cái nào**

- SSR (Server-Side Rendering) — render mỗi request, data luôn fresh, latency cao hơn
- SSG (Static Site Generation) — render lúc build, cực nhanh, data có thể stale
- ISR (Incremental Static Regeneration) — SSG + revalidate theo thời gian hoặc on-demand
- PPR (Partial Prerendering) — static shell + dynamic holes, Next.js 14+
- Streaming — render và gửi HTML từng phần, không block toàn bộ page

**4 Caching Layers trong Next.js**

- Request Memoization — deduplicate fetch trong cùng render tree
- Data Cache — persist fetch results qua nhiều requests
- Full Route Cache — cache rendered HTML + RSC payload
- Router Cache — client-side cache cho navigation
- Hiểu khi nào mỗi layer invalidate và cách opt-out

**Deployment & Edge**

- Vercel deployment — regions, edge functions, serverless functions
- Edge Runtime vs Node.js Runtime — trade-offs, limitations
- Image Optimization — `next/image`, formats, sizing, lazy loading
- Bundle analysis — `@next/bundle-analyzer`, tìm và fix bloat

### 2.3 — State Management & Data Fetching

**Phân loại state đúng trước khi chọn tool**

- Server state: data từ API — TanStack Query, SWR
- Client state: UI state, user preferences — Zustand, Jotai
- URL state: filters, pagination, search — `useSearchParams`
- Form state: React Hook Form

**TanStack Query (Server State)**

- `useQuery`, `useMutation`, `useInfiniteQuery`
- Stale time vs Cache time — khác nhau căn bản
- Query invalidation — khi nào và cách invalidate đúng
- Optimistic updates — update UI trước, rollback nếu fail
- Background refetching, focus refetching
- Dependent queries, parallel queries

**Zustand (Client State)**

- Store pattern — đơn giản hơn Redux, không có boilerplate
- Slices — chia store lớn thành pieces nhỏ
- Subscriptions — subscribe từng phần, không re-render toàn bộ
- Middleware: immer, devtools, persist

**React Hook Form + Zod**

- Controlled vs Uncontrolled — RHF dùng uncontrolled, nhanh hơn
- `register`, `watch`, `setValue`, `trigger`
- Zod schema — type-safe validation, inference từ schema ra TypeScript type
- `zodResolver` — kết nối Zod với RHF
- Error handling, nested fields, arrays

### 2.4 — Node.js Production

**Runtime & Framework**

- Fastify hoặc Hono — nhanh hơn Express, type-safe hơn, production-ready hơn
- Middleware pattern — request lifecycle, error propagation
- Plugin system (Fastify) — encapsulation, dependency injection
- Graceful shutdown — xử lý SIGTERM, drain connections trước khi tắt

**Authentication Production-Grade**

- JWT: access token (short-lived) + refresh token (long-lived, HttpOnly cookie)
- Refresh token rotation — mỗi lần dùng refresh token thì issue cái mới, invalidate cái cũ
- OAuth2 + PKCE — Authorization Code flow cho web app, không dùng Implicit flow
- Session management — server-side sessions, Redis store
- Password hashing: bcrypt hoặc Argon2, tại sao không dùng MD5/SHA1

**Database Layer**

- PostgreSQL — không chỉ biết query, biết tại sao query đó nhanh hay chậm
- EXPLAIN ANALYZE — đọc query plan, nhận ra Seq Scan vs Index Scan
- Index design — B-tree, partial index, composite index, khi nào index làm chậm hơn
- Transactions — ACID, isolation levels, khi nào cần transaction
- Prisma hoặc Drizzle — ORM không che giấu SQL, biết SQL được generate ra
- N+1 problem — nhận ra và fix bằng include/join
- Connection pooling — PgBouncer hoặc Prisma Accelerate

**Redis**

- Caching pattern: cache-aside (lazy loading) vs write-through
- TTL strategy — khi nào expire, khi nào invalidate manually
- Rate limiting — sliding window với Redis sorted sets
- Session storage — lưu session data thay vì JWT stateless
- Pub/Sub — real-time features, event broadcasting
- BullMQ — background jobs, queues, retry logic

**File Upload & Email**

- Multipart upload — stream lên S3/R2 trực tiếp, không buffer trên server
- Presigned URLs — client upload thẳng lên storage, bypass server
- Email: Resend hoặc Nodemailer + SMTP — transactional email, templates

### 2.5 — TypeScript Nâng cao

Không phải TypeScript cơ bản. Đây là thứ phân biệt người dùng TypeScript với người hiểu TypeScript.

- Generics có constraints: `<T extends object>`, `<T extends keyof U>`
- `infer` keyword — extract type từ trong type khác
- Conditional types: `T extends U ? X : Y`
- Mapped types: `{ [K in keyof T]: ... }`
- Template literal types: `type EventName = \`on${string}\``
- Discriminated unions — exhaustive checking với `never`
- `satisfies` operator (TS 4.9) — validate type mà không widening
- Declaration merging — extend module types
- Zod + inference: `z.infer<typeof schema>` — single source of truth cho type và validation

## Giai đoạn 3 — System Design & Architecture

Giai đoạn này không học thêm nhiều syntax. Học cách nghĩ ở cấp độ hệ thống — thiết kế, trade-off, scalability. Đây là thứ đưa từ Senior lên Staff/Principal.

---

### 3.1 — Frontend Architecture

**Design System**

- Token system — spacing, color, typography, không hardcode values
- Component API design — props contract, composition vs configuration
- Accessibility built-in — không phải afterthought
- Documentation: Storybook — visual testing, component catalog
- Versioning và breaking changes

**Monorepo với Turborepo**

- Workspace packages — shared UI, shared types, shared utils
- Build pipeline — task dependencies, caching, parallel execution
- Code sharing strategy — tránh circular dependencies
- Publishing packages — internal vs external, changesets

**Micro-frontends (biết khi nào cần)**

- Module Federation — share code giữa các app riêng biệt
- Khi nào micro-frontend hợp lý — multiple teams, independent deploy
- Khi nào là over-engineering — small team, monolith vẫn tốt hơn
- Trade-offs: bundle duplication, version conflicts, testing complexity

**Performance Budgets**

- Định nghĩa budget: JS bundle size, LCP, INP, CLS
- Enforce trong CI — fail build nếu vượt budget
- Monitoring production — Real User Monitoring (RUM)
- Lighthouse CI — automated audits trong pipeline

---

### 3.2 — Backend Architecture

**Layered Architecture**

- Controller → Service → Repository pattern
- Tại sao tách layers — testability, single responsibility
- Domain logic trong Service, không trong Controller
- Repository pattern — abstract database access, dễ mock trong tests

**Event-Driven Architecture**

- Message queues: BullMQ với Redis — background jobs, retry, priority
- Job patterns: scheduled jobs, delayed jobs, recurring jobs
- Dead letter queue — xử lý failed jobs
- Pub/Sub: Redis Pub/Sub hoặc EventEmitter — decouple components
- Khi nào dùng event-driven — async operations, side effects, notifications

**Caching Strategy**

- Cache-aside (Lazy loading) — read miss → fetch DB → store cache
- Write-through — write DB và cache cùng lúc, luôn consistent
- Cache invalidation — khó nhất trong CS, các patterns: TTL, event-based, versioning
- Cache stampede — nhiều requests hit cache miss cùng lúc, cách phòng

**API Design Production**

- REST resource design — noun not verb, nested resources
- Pagination: cursor-based vs offset-based — cursor tốt hơn cho large datasets
- Versioning: URL versioning (`/v1/`) vs header versioning
- Rate limiting: fixed window, sliding window, token bucket
- Circuit breaker — fail fast khi downstream service down
- Idempotency keys — safe retry cho mutation operations

---

### 3.3 — Infrastructure & DevOps

**Docker**

- Dockerfile best practices — multi-stage builds, layer caching
- `.dockerignore` — không copy node_modules vào image
- docker-compose — local development environment
- Image size optimization — alpine base, production dependencies only

**CI/CD với GitHub Actions**

- Pipeline: lint → type-check → test → build → deploy
- Environment secrets management
- Preview deployments — mỗi PR có environment riêng
- Rollback strategy — deploy fail thì tự động rollback

**Observability — Logs + Metrics + Traces**

- Structured logging — JSON logs, không phải plain text. Pino cho Node.js
- Log levels — error, warn, info, debug — dùng đúng level
- Metrics: request rate, error rate, latency (p50, p95, p99)
- Distributed tracing — trace một request qua nhiều services
- Alerting — alert khi error rate tăng, latency tăng, disk full

**Cloud Basics**

- Vercel — serverless functions, edge network, preview deployments
- Railway hoặc Render — full Node.js server, Postgres, Redis managed
- Cloudflare — CDN, DNS, Workers (edge compute), R2 (object storage)
- AWS fundamentals — S3, RDS, ElastiCache, CloudFront, EC2 vs ECS

---

### 3.4 — System Design Concepts

**Scalability**

- Horizontal vs Vertical scaling — scale out vs scale up
- Stateless services — không lưu state trong process, dễ scale
- Load balancing — round-robin, least connections, sticky sessions
- Auto-scaling — scale theo CPU, memory, request count

**Database Scaling**

- Read replicas — scale reads, không writes
- Connection pooling — tại sao direct connection tới Postgres có limits
- Database sharding — horizontal partitioning, phức tạp và thường không cần
- CQRS — Command Query Responsibility Segregation, tách read/write model

**Distributed Systems Concepts**

- CAP theorem — Consistency, Availability, Partition tolerance — chỉ được 2
- Eventual consistency — không phải mọi thứ cần strong consistency
- Idempotency — operations có thể gọi nhiều lần mà kết quả như nhau
- Distributed transactions — 2-phase commit, Saga pattern

## Giai đoạn 4 — Build & Ship

Đây không phải giai đoạn học thêm concept. Đây là nơi mọi thứ trước đó được kiểm chứng bởi thực tế.

---

### Tiêu chí của "thật"

Không phải todo app. Không phải clone Netflix. Một sản phẩm đạt tiêu chí sau:

- Có người dùng thật ngoài bạn — dù chỉ 10 người
- Deploy trên production thật — không phải localhost
- Có data thật cần bảo vệ — auth, authorization, data privacy
- Có performance issue thật phải debug — không phải benchmark giả
- Có security concern thật phải xử lý — input validation, rate limiting, CORS
- Có uptime requirement — app down là vấn đề thật

---

### Những thứ chỉ học được khi ship

**Technical debt thật** — quyết định nhanh để ship, rồi phải trả nợ sau. Học cách triage debt, không phải tránh hoàn toàn.

**Incident response** — production down lúc 2 giờ sáng. Debug mà không có local repro. Rollback trong khi user đang dùng. Không có tutorial nào dạy được cảm giác này.

**Backwards compatibility** — có user thật nghĩa là không thể breaking change tuỳ tiện. Database migration với zero downtime. API versioning vì client cũ vẫn còn dùng.

**Monitoring thật** — alert lúc 3 giờ sáng vì error rate tăng. Mở Grafana tìm bottleneck. Đọc logs tìm root cause. Thứ này chỉ học được khi có production thật.

**Trade-off dưới áp lực** — build fast vs build right. Ship feature vs fix tech debt. Không có câu trả lời đúng tuyệt đối — chỉ có quyết định phù hợp với context.

---

### Gợi ý loại sản phẩm để build

Không cần ý tưởng to. Cần ý tưởng đủ để có user thật:

- Tool giải quyết vấn đề bạn đang gặp trong công việc — khả năng cao có người khác cũng gặp
- SaaS nhỏ với free tier — một tính năng làm thật tốt, trả phí để dùng thêm
- Internal tool cho team — không cần public, nhưng có người dùng thật
- Open source project có adoption — người khác dùng và report issue
